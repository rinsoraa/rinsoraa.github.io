# 回忆整理台 · 本地使用说明

打开网站的 memory-editor.html，或项目编辑台中的“管理回忆照片”。这是静态客户端工具，不是具有服务器认证的后台。无需 Token，不扫描私人目录，远端发布保持 DISABLED。

## 整理一页

1. 新建，或选择现有回忆。稳定 ID 自动建立后只读，编辑不会更换身份。
2. 填写实际事件日期、标题、分类、说明、故事和标签。日期不从照片文件推断。分类可明确新增，不能覆盖已有名称。
3. 主动选择 PNG / JPEG / WebP。单张最多 12 MiB、16,777,216 像素，每边最多8192px，串行解码。所有草稿部署资源共最多64 MiB；低内存设备请分批处理。
4. 封面有限次等比例生成720–960px、quality .88–.90 WebP；普通建议≤120 KiB、精选≤200 KiB。无法达到时提示复核，不无限压低画质。高清查看图最长边3200px、quality .94；小图不放大。原件请自行保留，输出不携带原EXIF或输入文件名。
5. 补全 alt / 图片说明，排序图集，填写来源并确认公开。用户声明不等于独立版权认证。
6. 更新展示预览：使用照片墙同一组件，可看普通/精选卡、390px 排版和详情。草稿未写入正式 JSON。
7. 导出 ZIP。导出器重新读取实际 ZIP，核对目录、CRC、SHA256、尺寸与配置。下载只是取得资源包，尚未导入或发布。

草稿仅在当前页面内存，刷新或离页前请导出。取消读取时会丢弃结果，已开始的浏览器编码在结束后释放；不是可中断的后台任务。来源、故事与照片是否包含隐私由用户审查。不要把私人原件或凭据放进仓库。

## v1 的封面 / 高清关系

数据仍为 schemaVersion 1，不新增记录字段。轻量图用于 cover，高清图置于 gallery。管理器生成：

    assets/memories/<id>/m-<输入SHA前24位>-<派生SHA前24位>-cover.webp
    assets/memories/<id>/m-<相同输入SHA前24位>-<派生SHA前24位>-detail.webp

符合此明确约定且存在匹配高清图时，详情第一张使用高清图，省去低清封面的重复页；之后按 gallery 顺序显示。旧任意文件名仍保持 cover-first，现有记录无需迁移。checker 的 media() 继续包含封面和全部图集；detailMedia() 只控制观看顺序。

gallery 仍最多12个位置，封面高清图占一个，因此通常最多再添加11张。此图固定为详情第一张，其余可排序；替换封面同时更换配对引用，旧文件不会自动删除。

## 本地导入（默认只读）

先备份仓库。在包含本管理器的代码版本中运行：

    node tools/import-memory-gallery.cjs <ZIP文件或解压目录>

DRY_RUN 完整检查，但不创建锁、备份、媒体或 JSON。审查无误后明确执行：

    node tools/import-memory-gallery.cjs <同一ZIP文件或解压目录> --apply
    node tools/check-memory-gallery.cjs
    node tools/check-project-lab.cjs
    python tools/check-site.py

刷新 ?ui02=1&memory=1#moments 查看。新增一页或更新已有 ID，不写 Moments、项目列表或项目媒体。没有 Git 操作或网络写入。测试包只可在独立副本额外指定 --allow-fixture；正式数据不应使用该参数或加入测试图片。

包包含 manifest.json、memory-patch.json、IMPORT.md 及本次新增的派生资源。修改记录但未修改图片时可只导出引用补丁，不重新打包旧媒体。基线哈希绑定目标记录，允许其他记录独立变化；分类只作显式追加。完全相同的重复包返回 ALREADY_IMPORTED，不重复创建回忆。

## 冲突与恢复

- 相同文件名但内容不同、目标记录过期、冲突分类、非法路径、符号链接/junction、损坏或缺失资源，均在写入前拒绝。不要手改包指纹或换最新基线强行覆盖；重新打开管理页审查后导出。
- 支持本工具生成的单卷 ZIP STORE；不支持任意压缩包格式。ZIP 拒绝路径穿越、重复项、链接模式、非法目录和未声明数据。解压目录同样禁止链接和额外文件。
- 导入器先验证完整最终文档及所有引用文件的实际格式、尺寸和哈希；文件容器校验不是完整图像解码器，导出时另外执行浏览器解码验证，未知来源包仍应先在副本试验。
- APPLY 使用本地协作锁；备份保存在 .memory-import-backups/，日志为 .memory-import-journal.json，最后替换 JSON。只回滚本次新建且字节未变化的媒体，不删除旧文件。
- 多文件复制和 JSON 替换不是一个跨进程事务。协作锁约束本工具的并发；外部编辑器仍须避免同时修改。突然退出可能留下不可见的孤立媒体，日志列出计划路径和哈希。保留备份、日志及错误中的恢复清单，人工比较后再操作；不自动清理、不删除别人改变的文件。
- 未完成 journal 或已有 lock 会拒绝再次 APPLY。先确认没有活动导入，审查 current JSON 与备份、列表文件及哈希，不能直接盲删锁/日志重试。

备份、锁、journal、临时 JSON 已加入本地忽略规则，不应公开提交。下载、导入本地仓库、Git 提交、推送、部署是不同状态；本功能不授予后面几个步骤的权限。
