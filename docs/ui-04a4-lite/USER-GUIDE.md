# 手动管理作品素材

## 本地准备

1. 从项目编辑台点击“管理作品素材”，或直接打开 `project-media-editor.html`（通过本地网站服务/HTTPS打开，不能双击file://使用）。
2. 选择作品；名称/分类/状态只读，仍由原项目编辑台维护。
3. 从电脑主动选择文件。PNG/JPEG/WebP将等比输出WebP；视频仅支持完整、有限时长的WebM/VP8，不接受MP4，也不自动转码。选择、预览都不会上传。
4. 填写alt、说明；调整图集顺序。动态体验每个项目只配置一种：视频或对比。视频需要同宽高比Poster；对比需要同场景与对齐说明。
5. 填写本次新素材的来源、日期、版本与说明。确认已经检查私人信息与公开许可；新体验还需确认项目来源声明。文件技术校验不等于独立核验真实运行。
6. 点击“检查并导出本地资源包”。保留下载的ZIP，以及自行备份的输入原件。页面刷新/关闭会丢失内存草稿。

限制：图片≤12MiB/1200万像素/8192px，图集≤12张；视频≤32MiB/120秒/4096px；全部草稿部署资源≤64MiB。大文件会增加浏览器内存；优先选择短视频及适度分辨率。原件不打入包，清单保留原文件名/格式/尺寸/字节/指纹；生成的WebP移除EXIF。

## 导入本地仓库

下载不等于写入仓库。完整解压ZIP，并在兼容本阶段代码的项目根目录运行：

```sh
node tools/import-project-media.cjs "<解压后的rinsora-project-media-项目ID目录>"
```

这条只读检查：目录、SHA256、二进制元数据、配置、当前单项目媒体基线及现存同名文件。看到DRY_RUN_PASS后，先备份仓库，再明确执行：

```sh
node tools/import-project-media.cjs "<同一目录>" --apply
node tools/check-project-lab.cjs
python tools/check-site.py
```

LOCAL_IMPORTED只表示本地导入。刷新 `?ui02=1&lab=1#projects` 查看实际结果；仍需要独立审查和用户手动执行Git提交、同步与部署。工具不做这些操作。

## 冲突与恢复

- 基线不一致：重新打开管理器读取最新版本，重做或复核草稿。不要编辑指纹绕过检查。其他项目有变化可以保留，但同一项目媒体变化会拒绝旧包。
- 同名不同内容：拒绝覆盖。新部署名含内容哈希，正常重新选择文件会生成新名字；相同字节只复用，不覆盖。
- 文件缺失/损坏/比例错误：保留现有配置，修正原件或重新导出。
- 导入中断：配置最后替换；普通异常回收仅本次新建且字节未变的媒体，旧文件不会删除。强制终止/断电不保证多文件原子性：检查Git差异及manifest，新写但未引用的媒体可保留，重新检查后再决定处理。
- 撤销草稿：回到页面读取的原状态，不删除磁盘或远端文件。若要回退已导入配置，用先前快照/源码副本复核后恢复，仅移除媒体引用，不盲目删除旧文件。

## 远端发布

本版为REMOTE_PUBLISH_DISABLED。没有可执行的GitHub发布处理器，Token有无均不能触发写入。仓库/分支只显示已有设置，不能把main默认配置当成兼容版本证明。未来须独立实现并验证权限、兼容分支/版本、严格冲突、覆盖确认以及非原子多文件失败恢复后再启用。

本页不显示或导出Token；旧编辑台localStorage凭据仍有同源脚本读取风险。隐藏入口不是访问控制。这里不采集私人QQ、记忆、桌面或其他程序，只处理你主动选择的文件。
